# AGENTS.md

Operating notes for AI/agent sessions working in this repo. Read first.

## Hard rules

1. **Never write Blizzard credentials to a file that gets committed.** Locally they live only in `.env` (gitignored); in CI they live only in the repo's encrypted GitHub Actions secrets (`BLIZZARD_CLIENT_ID` / `BLIZZARD_CLIENT_SECRET`).
2. **Never hardcode the expansion, patch, or season ID anywhere.** They must come from `discover.mjs` at scraper boot. If you see a hardcoded `12.1.0`, `midnight`, or `18` in `scripts/`, it's a bug. (The period `1078` is the most recently discovered value; treat it as an example, not a constant.)
3. **Never hand-edit `data/aggregated_bis.json`.** It is generated by `scripts/run-once.mjs`. Bulk corrections to existing data go through the committed one-off scripts (see File touch map) which validate against the schema before writing.
4. **`scripts/verify-credentials.mjs` must remain token-only.** No scraping, no `aggregated_bis.json` write, no spec fetch. If you find yourself wanting to "just fetch one profile" in the verifier, create a new script instead.
5. **Data sources are two-tier.** Candidate discovery comes from Raider.IO's per-spec rankings endpoint (`scripts/lib/raiderio.mjs`); gear, talents, items, and item media come from the official Blizzard Game Data API. Don't swap one for the other.

## Daily commands

```
# Sanity check Blizzard OAuth
node scripts/verify-credentials.mjs

# Discover current season/period without fetching anything
node scripts/run-once.mjs --dry-run

# Run for a single spec
node scripts/run-once.mjs demon-hunter-havoc

# Synthetic smoke test (no network)
node scripts/smoke-aggregate.mjs

# Serve the static site
cd public && npx http-server -p 8080
```

## Data refresh automation (primary path)

`.github/workflows/scrape.yml` runs the full scrape **twice daily (09:00 & 21:00 UTC)** on GitHub Actions, commits fresh data as `github-actions[bot]`, and the push auto-triggers the Pages deploy. Your PC is not in the loop.

```
# Manual trigger from a terminal
gh workflow run scrape.yml --repo gitgipie/metagor

# Watch the latest run
gh run list --repo gitgipie/metagor --workflow scrape.yml --limit 1
```

- CI credentials come from repo secrets — set via `gh secret set BLIZZARD_CLIENT_ID/SECRET`.
- Cold-cache full runs take **2–3 hours** (workflow timeout is 4h). Don't lower it.
- Local runs still work identically (`node scripts/run-once.mjs`); CI just makes them unnecessary.

## File touch map

- `data/aggregated_bis.json` — auto-generated. Do not hand-edit.
- `data/guides.json` — hand-curated + consumables refreshed by the scraper. OK to edit.
- `data/schema/*` — JSON Schema. Update when contract changes (and bump `schema_version`).
- `public/js/registry.js` — class/spec catalog. Single source of truth for class colors, armor types, and slot layout.
- `public/js/app.js` — entry point. Fetches two JSONs, dispatches to renderers.
- `public/js/icons.js` — shared icon URL builder (Blizzard file_data_id CDN vs zamimg texture names).
- `public/js/render/*.js` — one renderer per UI block. Keep them pure: input data, mutate the host.
- `public/styles/*` — visual layer.
- `scripts/lib/config.mjs` — non-volatile config (region, locale, namespaces, rate limits, spec catalog).
- `scripts/lib/cache.mjs` — disk-backed TTL cache (`data/cache/`, gitignored).
- `scripts/lib/blizzard.mjs` — Blizzard OAuth + profile + static item + media. `.env` optional when `BLIZZARD_*` env vars exist (CI).
- `scripts/lib/raiderio.mjs` — season discovery + per-spec M+ rankings (candidate pool).
- `scripts/lib/leaderboard.mjs` — period/dungeon discovery helpers.
- `scripts/lib/discover.mjs` — boot-time version discovery (season, period, patch, expansion).
- `scripts/lib/aggregate.mjs` — pure tally logic + `classifyItemSource` (evidence-based source labels).
- `scripts/lib/dungeon-items.mjs` / `raid-items.mjs` — journal loot maps (item → dungeon/raid/boss). 7-day cache; rebuild if Blizzard lists new drops late.
- `scripts/lib/talent-tree.mjs` — talent tree structure fetch for the visual modal.
- `scripts/lib/icy-veins.mjs` — consumables scrape.
- `scripts/lib/resolve-consumables.mjs` — Blizzard static item name lookup.
- `scripts/lib/schema-validate.mjs` — AJV validator.
- `.github/workflows/scrape.yml` — scheduled scrape + auto-commit (see Automation above).
- `.github/workflows/deploy-pages.yml` — Pages deploy on push (stages `public/*` + the two data JSONs).
- One-off data-repair scripts (committed, safe to re-run): `refresh-meta.mjs`, `reclassify-sources.mjs`, `enrich-dungeon-labels.mjs`, `fix-catalyst-labels.mjs`, `restore-raid-difficulty.mjs`, `re-enrich-sources.mjs`, `test-classify-source.mjs`.

## Spec ID convention

Always `<class-slug>-<spec-slug>`, e.g. `demon-hunter-havoc`, `mage-arcane`. Used as the key in both `aggregated_bis.json` and `guides.json`. Cross-reference: `scripts/lib/config.mjs` SPECS array has both our slug and Blizzard's `blizzardClassId` / `blizzardSpecId` for each.

## Slot names

The 16 equipment slots: `head neck shoulders back chest wrists hands waist legs feet finger1 finger2 trinket1 trinket2 mainhand offhand`. The renderer maps to display labels; the data file uses these keys.

## Operational notes

**Blizzard throttling.** After ~736 leaderboard calls in a single script invocation, Blizzard's profile API starts returning 403 for several minutes. Mitigations: 12h leaderboard disk cache, 3s pause after the leaderboard batch, sequential profile fetches with 400ms spacing. Many `403`s in a run = real throttle; wait 5-10 minutes and re-run — the cache means the next run skips the leaderboard batch entirely. On CI this manifests as a failed workflow run; the next cron slot retries.

**Stale journal loot lists.** Blizzard's journal-instance loot tables lag new raid tiers by days. If raid items show bare `Raid` without a raid name / BOSS line, delete `data/cache/blizzard_item-to-raid-map.json` and run `node scripts/re-enrich-sources.mjs` (rebuilds the map + re-enriches the data).

**Crest/upgrade tracks.** `public/js/render/gear.js` has no rank display anymore (removed for consistency); item source labels are deliberately bracket-free (`Raid · <Name>`, `Mythic+ · Tier` — never `Raid (Heroic)`, never `Mythic+ (Catalyst)`). Keep it that way: the source tag must not claim origins Blizzard's data can't prove.

## Deploy

`deploy-pages.yml` deploys to **GitHub Pages** on every push to `main` (stages `public/*` + `data/aggregated_bis.json` + `data/guides.json` into `_site`). No build step. Live at `https://gitgipie.github.io/metagor/`. Fresh data reaches the site via the scheduled scrape's bot commit, or any manual push.
