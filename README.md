# Meta'gor

A single-pane-of-glass dashboard for **World of Warcraft: Midnight** Mythic+ best-in-slot gear, talents, consumables, and content creators. Gear and stats are **live-aggregated** from the top Mythic+ performers per spec (Raider.IO per-spec rankings → Blizzard profile API), resolved through the official Blizzard Game Data API. Consumables, rotations, and creator links are **hand-curated**.

The site is fully static — no backend, no server. A scheduled GitHub Actions workflow scrapes fresh data twice daily, commits it, and GitHub Pages serves the result. No homelab, no local machine dependency.

## Stack

- **Frontend** — vanilla ESM (no framework), 3-pane layout, Wowhead tooltips via `power.js`, shared icon helper (`public/js/icons.js`).
- **Scraper** — Node.js 20+ ESM, running on GitHub Actions (cron 2× daily) or locally via `node scripts/run-once.mjs`.
- **Data sources** — Blizzard Developer Portal (free, client_id + client_secret) + Raider.IO per-spec rankings (candidate discovery only; all item/talent data comes from Blizzard).
- **Hosting** — GitHub Pages via `.github/workflows/deploy-pages.yml`.

## Provision (one-time)

1. Sign in at https://develop.battle.net (any Battle.net account works).
2. **My Account → API Access → Create a new client**.
3. **Name:** `Meta'gor`. **Service:** World of Warcraft. **Redirect URL:** blank.
4. Submit. Copy the **Client ID** and **Client Secret** (the secret is only shown once).
5. Local runs: paste them into `.env` at the project root:
   ```
   BLIZZARD_CLIENT_ID=...
   BLIZZARD_CLIENT_SECRET=...
   ```
6. CI runs: set them as repo secrets instead (`gh secret set BLIZZARD_CLIENT_ID` / `BLIZZARD_CLIENT_SECRET`).

## Run the credential sanity check

Confirms Blizzard accepts the credentials. **No scraping, no data written.**

```
node scripts/verify-credentials.mjs
```

A green light = ready to run the scraper.

## Run the static site locally

```
cd public
npx http-server -p 8080
```

Or any other static file server pointed at `public/`.

## Update data

**Primary path — automatic:** the GitHub Actions workflow (`.github/workflows/scrape.yml`) runs the full scrape twice daily (09:00 & 21:00 UTC) and commits fresh data as `github-actions[bot]`; the push auto-deploys. Manual trigger:

```
gh workflow run scrape.yml --repo gitgipie/metagor
gh run list --repo gitgipie/metagor --workflow scrape.yml --limit 1
```

**Local path (identical code):**

```
node scripts/run-once.mjs --dry-run            # discovery only, no fetches
node scripts/run-once.mjs demon-hunter-havoc   # one spec only
node scripts/run-once.mjs                      # all 40 specs (slow, 2-3h cold)
```

The orchestrator:
1. Discovers the current M+ season + period from Raider.IO and Blizzard.
2. Fetches per-spec M+ rankings from Raider.IO (top 100 candidates per spec, all regions).
3. Fetches Blizzard character equipment + specializations + statistics for the top 50.
4. Aggregates into `data/aggregated_bis.json` (evidence-based source labels).
5. Merges the visual talent tree structure from Blizzard's talent API.
6. Resolves consumable item names, scrapes Icy Veins consumables (writes back to `guides.json`).
7. Validates against `data/schema/aggregated_bis.schema.json`.
8. Atomic-writes the result.

After local data is fresh:
```
git add data/aggregated_bis.json data/guides.json
git commit -m "data: refresh"
git push                          # GitHub Pages auto-deploys
```

## Known operational constraints

- **Blizzard throttling:** after ~736 leaderboard calls in one invocation, the profile API returns 403s for several minutes. The scraper paces requests and caches to disk; on CI a throttled run fails and the next cron slot retries.
- **Stale journal loot lists:** Blizzard's journal-instance loot tables lag new raid tiers by days. If raid items show bare `Raid` without a raid name / BOSS line, delete `data/cache/blizzard_item-to-raid-map.json` and run `node scripts/re-enrich-sources.mjs`.
- **Private profiles:** top-of-leaderboard characters often return Blizzard 403. The scraper uses a 100-candidate buffer per spec to absorb skips.
- **Icon format change:** Blizzard's media API now serves icons as numeric `file_data_id`s (render CDN) instead of texture names; both formats are handled by `public/js/icons.js`.
